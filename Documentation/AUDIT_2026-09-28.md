# S21_HiJack Audit — 2026-09-28

## Executive summary

Since the [April audit](AUDIT_2026-04-27.md) the Rust daemon has grown from ~25.7k to ~75k LOC, adding a web monitor (axum + WebSocket), the Pad-protocol client, MIDI/D700 sidecar control, Stream Deck, MIDI triggers, backups/recovery, and two mobile clients. The toolchain hygiene the April audit asked for is in place and holding: **`cargo fmt --check` clean, `cargo clippy --all-targets -D warnings` clean, 828 tests passing (1 ignored)**.

The risks have moved from hygiene into three areas:

1. **Two ways to lose the show.** A single hostile/buggy UDP datagram aborts the whole process (stack overflow in the OSC bundle decoder — reproduced), and a save onto a full disk reports success while replacing the good show with a truncated one (tokio swallows the write error — confirmed from tokio's source).
2. **Lifecycle and lock-order bugs in the newer wiring.** The Mode 2 iPad link is never torn down on Disconnect (found independently by three reviewers), there are two lock-order cycles that can freeze UI + inbound + save together, and `New`/`Open` leave stale indexes and half of the previous show behind.
3. **Non-finite floats.** Nothing in the codebase checks `is_finite`. NaN/inf from the network or a text field can panic a recall, wedge dirty-suppression permanently, go to the console raw, and — because serde_json writes NaN as `null` — make the saved show file unloadable.

Plus one plain correctness bug with show impact: **outbound GP OSC always assumes 8 auxes**, so on any other aux/group split, writes to Group channels land on the wrong bus.

### Methodology

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, `cargo audit` on rustc 1.94.1 (Linux).
- Seven parallel deep reviews by subsystem (network servers; console pipeline & concurrency; iPad/Pad protocol & parsers; hardware sidecar/Stream Deck/MIDI; persistence/model/platform; egui UI; mobile apps/packaging/CI). Every Critical and most High findings were then re-verified by reading the cited code directly; the two Criticals were reproduced/confirmed against dependency source.
- Static analysis plus small out-of-tree repro programs only. No hardware, no device testing of the mobile apps.
- Threat model unchanged from April: closed show LAN, operator-controlled devices. Findings that only matter on a hostile network are rated accordingly; findings a *misbehaving* peer or a typo can trigger are not discounted.

## Critical

### C1 — Nested OSC bundle aborts the process

**Where:** [src/osc/mod.rs:37](../src/osc/mod.rs#L37) `decode_udp_tolerant` → `rosc 0.10.1` `decoder.rs` (`decode_packet` ↔ `decode_bundle` recurse with no depth limit). Reached from 64 KiB receive buffers at [src/osc/client.rs:226](../src/osc/client.rs#L226) (GP), [src/osc/ipad_client.rs:163](../src/osc/ipad_client.rs#L163) (Mode 2 / Pad), [src/console/ipad_connection.rs:356](../src/console/ipad_connection.rs#L356) (Mode 3 iPad listen port).

**What:** Each nesting level costs 20 bytes, so ~2,800 levels fit in a 56 KB datagram. Reproduced out-of-tree against rosc 0.10.1 on a 2 MiB stack (tokio's default worker stack): `thread has overflowed its stack — fatal runtime error: stack overflow, aborting`. Debug builds die at ~1,000 levels. A stack overflow is an abort, not a panic — nothing catches it.

**Scenario:** Any host on the LAN sends one datagram to the Mode 3 iPad port (not source-filtered) or the GP/Mode 2 local port (GP ignores the sender — see M9). The daemon and UI vanish mid-show.

**Not affected:** monitor server and trigger listener use 4 KiB buffers (≤ ~200 levels — safe).

**Fix:** Before calling rosc, walk bundle headers iteratively and reject datagrams nested deeper than ~8 (DiGiCo never nests). Add a bundle-aware proptest strategy for `decode_udp_tolerant`.

### C2 — Failed save reported as success

**Where:** [src/persistence/show_file.rs:306-311](../src/persistence/show_file.rs#L306-L311); same pattern in [src/persistence/backup.rs:203-207](../src/persistence/backup.rs#L203-L207).

**What:** `tokio::fs::File::write_all` hands the final buffer to a blocking task and returns `Ok` immediately. `sync_all()` then calls `complete_inflight()`, which on error only stores `last_write_err` and returns `()` (tokio 1.52.3 `fs/file.rs:317-322, 1079-1088`); the fsync itself succeeds. The error is dropped with the file handle. A reviewer confirmed it end to end under `ulimit -f`: the write failed at 20 KB and `write_all` + `sync_all` both returned `Ok`.

**Scenario:** A disk is full (e.g. a Pi SD card filled by logs, see M13). The operator hits Save; a truncated `.tmp` is renamed over the good show and the UI says "Saved". Autosaves then rotate out the good backups with equally truncated copies.

**Fix:** `file.flush().await?;` before `file.sync_all().await?` in both places (verified to surface the error). Or do the whole write+fsync+rename inside one `spawn_blocking` with `std::fs`.

## High

### H1 — GP OSC bus numbering is asymmetric

**Where:** encode [src/model/channel.rs:36-41](../src/model/channel.rs#L36-L41) (Aux n → 69+n, Group n → 77+n, always); parse [src/model/channel.rs:59-83](../src/model/channel.rs#L59-L83) (counts through `mix_output_types`). Used by [src/osc/encode.rs:52,63](../src/osc/encode.rs#L52).

**What:** The desk's 24-bus pool is split between auxes and groups by configuration. Inbound parsing honours the split; outbound always assumes 8 aux. On a 10-aux/14-group desk, inbound bus 78 is Aux 9 but outbound `Group(1)` is also sent to 78. On a 6-aux desk, Group 1 is really bus 76.

**Consequence:** Recalls, gangs and macros that target Group channels (or Aux 9+) write the wrong bus. Related:
- `mix_output_types` is only regenerated when empty ([src/console/discovery.rs:30](../src/console/discovery.rs#L30)), so it goes stale after a desk reconfiguration or when it's restored from an old show file.
- Any path ending in `/types` replaces it ([src/osc/ipad_parse.rs:196](../src/osc/ipad_parse.rs#L196)).
- A free-text "CG 11" macro target encodes to 120, which is Matrix 1.

**Fix:** Add a config-aware `to_gp_osc_number_with_config` (the inverse of the parser) with per-type range checks, and use it on the send path. Add a proptest round trip under non-default `mix_output_types`.

### H2 — Mode 2 iPad link is never shut down

**Where:** [src/console/ipad_connection.rs:67](../src/console/ipad_connection.rs#L67) uses `client.into_parts()` (a fresh, never-cancelled token); the mirror task at `:88` has no cancel; the UI drops the handle ([src/ui/setup_tab.rs:2449](../src/ui/setup_tab.rs#L2449)). `receive_loop` doesn't exit when its channel closes ([src/osc/ipad_client.rs:191](../src/osc/ipad_client.rs#L191)).

**Scenario:** After Disconnect, the old socket and mirror loop keep writing the shared state and dirty tracker. They also keep running gang and pan-link propagation to the desk through the old senders, and keep `snap_event_tx` alive, so follow mode can still fire recalls. Every reconnect adds another set, so propagation doubles each time. A fixed local port on reconnect gets EADDRINUSE (macOS) or split delivery (Linux).

**Fix:** Pass the connection token into `connect_mode2`, use `into_parts_with_cancel(token)`, and `select!` on it in `ipad_state_mirror_loop`.

### H3 — Non-finite floats are accepted everywhere

**Where:**
- Network input: [src/osc/parse.rs:171](../src/osc/parse.rs#L171) `extract_float`; [src/osc/ipad_parse.rs:403](../src/osc/ipad_parse.rs#L403); inline `"nan"`/`"inf"` at [src/osc/ipad_client.rs:243](../src/osc/ipad_client.rs#L243); [src/web/protocol.rs](../src/web/protocol.rs) (serde parses `1e39` to `inf`); the UDP monitor server.
- UI text fields: `parse_timing_secs` at [src/ui/scope_editor/state.rs:533](../src/ui/scope_editor/state.rs#L533) (`clamp` passes NaN through), cue numbers, macro values, trigger args. Rust's float parser accepts "nan"/"inf" in any case.

**Consequences:**
- **Panic in a recall.** `Duration::from_secs_f32(NaN)` panics at [src/console/snapshot_engine.rs:1585](../src/console/snapshot_engine.rs#L1585) (also `:1587, 1600, 1937, 2029`). That happens inside `with_dirty_suppression` (`:667-681`), which is not panic-safe, so the suppression depth never comes back down. That permanently disables pan link, the palette absorb loop and autosave.
- **Unloadable show file.** serde_json writes NaN as `null` and refuses to read it back as `f32`, so the show and every later autosave fail to load and are classed as corrupt.
- **Raw values to the desk.** `inf`/`NaN` are sent to the console as-is (`/channel/70/fader inf`). A NaN in the mirror also defeats the monitor poll's `old == new` check, so the value is re-pushed forever.
- **Wrong value on `/sd`.** `normalized_to_db(NaN)` returns +10 dB.

**Fix:**
- Drop non-finite values in every `extract_*` and parse helper, and in every UI parse helper (`.filter(|v| v.is_finite())`).
- Clamp timings on show load.
- Use `Duration::try_from_secs_f32`.
- Make dirty suppression an RAII guard.

### H4 — Lock-order cycles can deadlock UI, inbound and save

tokio's `RwLock` is fair: a queued writer blocks new readers. Two cycles:

- **(a) Gangs.** The inbound path holds `gang_manager.read()` ([src/console/inbound.rs:176-180](../src/console/inbound.rs#L176-L180)) while `process_gang_update` takes `state.read/write` ([src/console/gang_engine.rs:202,252,341](../src/console/gang_engine.rs#L202)). `build_show_file` ([src/ui/setup_tab.rs:3186-3194](../src/ui/setup_tab.rs#L3186-L3194), used by autosave and Save) holds `state.read()` and then takes eight more reads including `gang_manager`. Pan link also takes `state` then `gang_manager`. Scenario: a gang fan-out is running during autosave while the operator toggles a gang (a queued `gang_manager.write()`). Nothing can make progress.
- **(b) Stream Deck.** `streamdeck_resize_and_collect_labels` ([src/ui/app.rs:1754-1780](../src/ui/app.rs#L1754-L1780), on the UI thread) holds `stream_deck_config.write()` while waiting for `macro_manager.read()`. `build_show_file` holds `macro_manager.read` while waiting for `stream_deck_config.read`. Inbound takes `macro_manager.write()` on every change.

**Fix:** In `build_show_file`, clone each manager and drop its guard before taking the next. In inbound, clone the matching gangs and drop `gang_manager` before propagating. Never `block_on` a lock from the UI while holding another. This also covers April's **H2** (gang lock held across sends), which is still open.

### H5 — UI panic on stale cue index

**Where:** `current_cue()` indexes `cues[i]` unchecked at [src/console/cue_manager.rs:212](../src/console/cue_manager.rs#L212). New Show ([src/ui/setup_tab.rs:1554](../src/ui/setup_tab.rs#L1554)) and show load (`:3267`) replace `cue_list` without resetting `current_cue_index`. [src/ui/snapshots_tab.rs:241](../src/ui/snapshots_tab.rs#L241) calls it every frame.

**Scenario:** The operator is on cue 12 and chooses New (or opens a show with fewer cues). The app crashes on the next frame.

**Fix:** Use `.get(i)`, and add a `replace_cue_list()` that also resets the index and `last_recalled`.

### H6 — Headless mode ignores the show file

**Where:** [src/main.rs:198-290](../src/main.rs#L198-L290). `args.show_file` is only passed to `run_ui` (`:669`).

**Scenario:** The README describes the headless Pi as a primary deployment. There, cue, macro, palette and gang managers start empty, so `/cue/go` and `/snapshot/recall` do nothing, with no warning.

**Fix:** Load `args.show_file` in `run_headless` and populate the managers and config (and warn loudly if none was given).

### H7 — Sidecar moves bypass the "operator change" pipeline

**Where:** [src/console/sidecar_service.rs:316-329](../src/console/sidecar_service.rs#L316-L329). The header comment at `:33-36` claims the console echo drives `maybe_override`. It can't: GP doesn't echo, and the iPad echo is marked as our own by `sent_log.is_echo` and skipped ([src/console/inbound.rs:129-186](../src/console/inbound.rs#L129-L186)). The optimistic mirror update also makes `old == new`.

**Consequence:** D700 or MIDI moves never cancel a running fade (the operator fights the automation), never propagate through gangs or pan link, never mark the channel dirty, and never get recorded in macro learn. `Documentation/sidecar.md` test step 4 cannot pass.

**Fix:** Route hardware-originated sends through the same operator-change routine inbound uses: override registry, gang, pan link, dirty tracker.

### H8 — Unsaved edits lost without a prompt

**Where:** No show-level dirty flag exists. Closing the window while disconnected quits immediately ([src/ui/app.rs:2346-2354](../src/ui/app.rs#L2346-L2354)); Open and New replace the show without asking; untitled shows are never autosaved ([src/ui/app.rs:1788](../src/ui/app.rs#L1788)). Dropping the runtime on exit ([src/main.rs:699](../src/main.rs#L699)) also cancels an in-flight save.

**Scenario:** After hours of offline cue building in an untitled show, closing the window loses everything.

**Fix:** Keep a show-dirty generation, prompt on close, Open and New, autosave untitled shows to a scratch folder, and await any in-flight save before exit.

### H9 — Web monitor access control — **ACCEPTED 2026-09-28**

**Status:** Accepted by operator decision. Open access to the HTML monitor is intentional; the deployment relies on network security. The observations are kept below for the record. M17 (WebSocket sessions outliving shutdown) is a lifecycle bug rather than access control, so it stays open.

**Where:** [src/web/mod.rs](../src/web/mod.rs), [src/ui/setup_tab.rs:2773](../src/ui/setup_tab.rs#L2773), [src/main.rs:545](../src/main.rs#L545).

The web monitor is new since April and on by default. It has several gaps that stack:
- **No Origin check on the WebSocket upgrade (`mod.rs:123`).** Any web page opened on a musician's phone on the show Wi-Fi can open `ws://<daemon>:8080/ws`, send `hello` with a profile name, and take over that mix. That page can also brute-force PINs, because failed attempts aren't rate-limited.
- **Binds `0.0.0.0` regardless of the interface selection.** Unlike the UDP listeners, it ignores the selected interface, so a dual-homed laptop serves mix control on the venue Wi-Fi too.
- **tungstenite defaults.** Messages up to 64 MiB, no `Hello` timeout, no idle timeout and no connection cap mean a few peers can push the daemon to OOM or exhaust file descriptors.
- **PIN is advisory while UDP is open.** It is documented as web-only ([src/model/monitor.rs:31-34](../src/model/monitor.rs#L31-L34)), but the UDP monitor path (port 8025, on by default) accepts the same profile name with no PIN. It rebinds the endpoint and returns full mix state.

**Fix:**
- Check `Origin` against `Host` (or an allowlist).
- `ws.max_message_size(4096)`, a `Hello` timeout, a connection cap, and a per-IP backoff after failed PINs.
- Bind the web server to the selected interface.
- Either refuse UDP commands for PIN-protected profiles or document plainly that a PIN only works with UDP monitoring disabled.

### H10 — Android app: faders drive the previously shown aux

**Where:** `pointerInput(Unit)` captures the first composition's `onDb`/`onPan` in [Faders.kt:76-84, 131-142](../monitor_android/app/src/main/java/com/pob31/s21monitor/ui/widgets/Faders.kt#L76-L84), and the strips aren't wrapped in `key()` ([MonitorScreen.kt:236-242](../monitor_android/app/src/main/java/com/pob31/s21monitor/ui/MonitorScreen.kt#L236-L242)).

**Scenario:** A musician switches from their in-ear aux to a wedge aux and drags a fader. The change goes to the in-ear aux they were looking at before.

**Fix:** `rememberUpdatedState(onDb)` / `rememberUpdatedState(onPan)` inside the gesture, plus `key(send.input, send.aux)` around each strip.

### H11 — Flutter Android 14+ foreground-service crash — **OUT OF SCOPE 2026-09-28**

**Status:** The Flutter app is not going to be used. Recorded for reference only.

**Where:** [monitor_app/android/app/src/main/AndroidManifest.xml](../monitor_app/android/app/src/main/AndroidManifest.xml) requests `FOREGROUND_SERVICE_DATA_SYNC` but never declares the plugin's service with a `foregroundServiceType`. [lib/services/background_osc_service.dart:47-55](../monitor_app/lib/services/background_osc_service.dart#L47-L55) doesn't pass `foregroundServiceTypes`. flutter_background_service 6.3.1 then calls `startForeground` with no type, which throws `MissingForegroundServiceTypeException` on API 34+. Traced through the plugin source; **not tested on a device**.

**Fix:** Declare `<service … foregroundServiceType="dataSync" tools:replace=…>` and pass `foregroundServiceTypes: [AndroidForegroundType.dataSync]`.

## Medium

**Connection lifecycle and UI**
- **M1 — A macro running [Disconnect, Connect] orphans the new connection.** In the same event drain, the `Disconnected` handler clears the *new* `cancel_token` ([src/ui/app.rs:1122](../src/ui/app.rs#L1122)). Disconnect can then no longer stop that session, and the next Connect stacks a second one. Tag the event with a connection generation.
- **M2 — The connect task ignores cancellation.** It sets `conn_flag` before a handshake that can take up to 5 s, then publishes the engines without checking `token.is_cancelled()` (setup_tab.rs:2270-2848). If Disconnect is pressed during the handshake, the UI shows "Connected" with dead engines.
- **M3 — `.expect()` on unvalidated IP strings.** `local_ip` from the show file and the Mode 3 iPad IP are parsed with `.expect()` ([src/ui/setup_tab.rs:2230, 2233, 2943, 2485](../src/ui/setup_tab.rs#L2230)). A trailing space or an IPv6 literal crashes the UI or leaves it stuck at "Connecting…". Trim and validate them up front.
- **M4 — New leaves most of the old show behind.** It clears cues, snapshots, macros and palettes only ([src/ui/setup_tab.rs:1545-1572](../src/ui/setup_tab.rs#L1545-L1572)). Gangs (still active on the desk), pan link, monitor clients, the Stream Deck and sidecar configs, and `console_recall` survive and get saved into the new show. `help.rs:1326` says gangs are cleared.
- **M5 — Show format version and forward-compatibility.**
  - The save path stamps `version: 18` ([src/ui/setup_tab.rs:3197](../src/ui/setup_tab.rs#L3197)), but the format is 19 ([src/persistence/show_file.rs:268](../src/persistence/show_file.rs#L268)); commit 5052155 missed it.
  - Opening a file from a newer build silently drops unknown fields, and re-saving downgrades it.
  - An unknown enum variant fails the whole load and is reported as "truncated or bad header".
  - Fix: one `SHOW_FORMAT_VERSION` constant, and refuse (or open read-only) any file with `version > current`.
- **M6 — The show path can end up pointing at the wrong file.** Recovery's "Load this" sets `show_file_path` to the *backup* ([src/ui/app.rs:2006](../src/ui/app.rs#L2006)), so later saves go into `.s21backups/` and get rotated out. After a failed load the path still points at the corrupt file while memory holds the previous show ([src/ui/setup_tab.rs:3381-3395](../src/ui/setup_tab.rs#L3381-L3395)), so the next Save or autosave overwrites that file with the wrong show.
- **M7 — Backup name collisions.** The name sanitiser maps every non-ASCII character and every space to `_` ([src/persistence/backup.rs:112-132](../src/persistence/backup.rs#L112-L132)). "My Show" and "My_Show", or two Cyrillic names of the same length, share one rotation, so one show's backups delete the other's. Append a short hash of the raw name.
- **M8 — The UI thread blocks on async locks.** `runtime.block_on(x.read())` is used in gangs_tab.rs:404 and monitor_tab.rs:130/388/705, while other tasks hold those locks across sends. The frame loop, including the GO transport, stalls under load. Use `try_read` with a cached copy, as the other tabs do.

**Console, iPad and Pad protocols**
- **M9 — GP receive ignores the sender and dies on Windows resets.** The GP receive loop never checks the sender address ([src/osc/client.rs:233](../src/osc/client.rs#L233)), so any host can inject values, including `/digico/snapshots/fire`, which drives follow mode. On Windows an ICMP unreachable (the console rebooting) shows up as `WSAECONNRESET`, which `break`s the loop (`:259-262`). `run_loop`'s `else => break` never fires, so inbound stops silently. Mode 3 has the same issue and also cancels the shared token (ipad_connection.rs:431). Filter on `console_addr`, and continue after `ConnectionReset`.
- **M10 — iPad bus counts read as per-type counts.** The captured S21 handshake reports `Aux_Outputs 17` / `Group_Outputs 17` against 8 aux + 9 group types. `apply_config_message` ([src/console/ipad_handshake.rs:329](../src/console/ipad_handshake.rs#L329)) stores 17/17, overwriting the GP counts, and `GroupSendOn(17)` then collides with `MasterBusOn`. *Interpretation inferred from the capture*; worth confirming on the desk.
- **M11 — Mode 2 discards the handshake config.** Only the name is logged (setup_tab.rs:2449, main.rs:381), so aux modes and types never reach `state.config` and Pan Link's `aux_mode()` stays `None`.
- **M12 — Pad connection link-loss detection and resync.**
  - The heartbeat only runs once the query queue is empty ([src/console/pad_connection.rs:355](../src/console/pad_connection.rs#L355)), so a dead desk shows "Connected" for the whole enumeration sweep.
  - The queue is built once, after an early handshake exit.
  - A session change isn't re-enumerated, although the module doc says it is.
  - A closed receive channel never sets `Lost`.
- **M13 — Logs grow without limit.**
  - The default filter is `s21_hijack=debug` in release builds ([src/logging.rs:29](../src/logging.rs#L29)), and every outbound OSC message is logged.
  - Every malformed packet produces an unthrottled `warn!`.
  - Rotation keeps 14 files with no size cap, and `crashes.log` is never rotated.
  - Together these fill SD cards, which then triggers C2.
- **M14 — CIDR allowlists fail open.** Invalid entries are skipped with a `warn!` ([src/persistence/show_file.rs:114-125](../src/persistence/show_file.rs#L114-L125)). If every entry is invalid (a trailing space, IPv6), the list is empty, which means "accept all". Deny all, or refuse to start, when a configured list parses to nothing.
- **M15 — Monitor input channel isn't bounds-checked.** When `visible_inputs` is empty, any `input_ch` is accepted ([src/console/monitor_engine.rs:276-303](../src/console/monitor_engine.rs#L276-L303)). `input=78` sends to GP channel 78, which is bus space. Apply `ChannelId::is_within_bounds`.
- **M16 — Monitor sends skipped by the 20 Hz rate limit are never re-pushed.** The generation check returns early on the next poll ([src/console/monitor_engine.rs:485-489, 559-563](../src/console/monitor_engine.rs#L485)), so other clients can miss the final fader value.
- **M17 — WebSocket sessions outlive server shutdown.** `handle_ws` never watches `cancel`. After Disconnect/Connect, browsers stay "online" and send into a dead channel without reconnecting.
- **M18 — Macro values and learn.** Relative steps aren't clamped ([src/console/macro_engine.rs:421-426](../src/console/macro_engine.rs#L421)), so pan beyond ±1 reaches the desk. Learn mode records our own echoes and the console-load flood into an unbounded Vec ([src/console/inbound.rs:193](../src/console/inbound.rs#L193)).

**Hardware integrations**
- **M19 — Sidecar encoders and motors are out of step with the desk.**
  - The relative-encoder accumulator is seeded only once ([src/console/sidecar_service.rs:254-260](../src/console/sidecar_service.rs#L254-L260)). After a recall, the next click jumps the parameter back to the pre-recall value plus one step.
  - Motor dedup compares against the last motor push, not the fader's actual position (`:473-476`). A touch-less motor board can be left 10 dB away from the console.
  - Motors are driven full-travel with no ramp, the end-stop slamming described in field note 23.
- **M20 — Sidecar learn mode swallows all input.** It stays armed through the Ready phase, and whenever the operator leaves the tab, until they come back and cancel ([src/console/sidecar_service.rs:189-195](../src/console/sidecar_service.rs#L189-L195)). Every bound fader is dead in the meantime. Disarm on detection, or add a timeout.
- **M21 — Relative-mode guessing gets MCU/D700 encoders wrong.** These encoders use sign-magnitude, which learn guesses as BinaryOffset or TwosComplement, so direction is reversed or the first counter-clockwise click reads as −63 ([src/console/sidecar_learn.rs:218-230](../src/console/sidecar_learn.rs#L218)). The comment at `model/sidecar.rs:93` is also wrong.
- **M22 — Stream Deck: held keys re-fire, and no auto-reconnect.**
  - `ButtonStateChange` carries the full key-state vector, and every `true` is emitted as a press ([src/console/streamdeck_engine.rs:330-339](../src/console/streamdeck_engine.rs#L330-L339)). Holding A while pressing B fires A's macro again.
  - There's no auto-connect at launch, after a replug, or on show load, although the docs promise it.
  - `enabled` isn't checked when firing.

**Android app and CI**
- **M23 — Android app protocol and platform issues.**
  - **Packet ordering:** `MonitorService.kt:260-271` starts one coroutine per packet, so packets can reorder and the desk can settle on a stale value.
  - **Throttling:** fader sends aren't throttled; every drag event becomes a packet.
  - **Android 15:** the ~6 h/day `dataSync` foreground-service limit isn't handled (`onTimeout`), which matters for a rehearsal followed by a show.
- **M24 — Release and CI pipeline.**
  - **Manual release:** `workflow_dispatch` checks out the default branch, not the tag. `actions/checkout` has no `ref` in [release.yml](../.github/workflows/release.yml), so untagged code can ship under a tag. Published releases are unaffected.
  - **Action pinning:** actions are pinned to tags, not SHAs, in jobs with `contents: write` that also receive signing secrets.
  - **Android app:** it isn't built in CI (`gradlew assembleDebug` would catch breakage from the frequent AGP/Gradle bumps).
  - **`cargo audit`:** RUSTSEC-2026-0285 in `rustls 0.23.41` (via `ureq`, the update checker) isn't on the CI ignore list, so the audit job should currently be red. `cargo update -p rustls` to ≥ 0.23.45.

## Low

**Protocol, parsing and CLI**
- **Band 0 underflow:** `EqBandGain(0)` from a show file underflows `b - 1` in `to_gp_osc_suffix` ([src/model/parameter.rs:207](../src/model/parameter.rs#L207)): a panic in debug builds, `eq/255` in release.
- **`total_bus_count` overflow:** it can overflow `u16` on unbounded wire counts ([src/model/config.rs:137](../src/model/config.rs#L137)).
- **Headless CLI:** `recv_port + 1000` overflows `u16` (main.rs:399). An invalid `--mode` silently becomes Mode 1. `.expect("Invalid iPad IP")` panics. Only Ctrl-C is handled, not SIGTERM, so a systemd stop skips the log flush.
- **Mode 3 source filtering:** it doesn't filter the iPad side by source address (`_src`, ipad_connection.rs:369), and it drops inline values that Mode 2 recovers.
- **Monitor profile enumeration** *(accepted with H9)*: `unknown_client` vs `pin_required` reveals which profile names exist.
- **Monitor and trigger handling:**
  - `/status/console` always reports connected (the value is hardcoded).
  - `/macro/fire` runs inline in the trigger loop, so a macro with delays holds up the next `/cue/go`.
  - QLab uniqueID replies are accepted from any source.
  - Snapshot names aren't escaped in the QLab customString.
- **Monitor relative-drag default:** a missing send level defaults to 0 dB (unity) as the starting point for a relative drag.

**Concurrency leftovers**
- **Fade deregistration race:** a finished fade deregisters without a generation check ([src/console/fade_engine.rs:299-303](../src/console/fade_engine.rs#L299)), so it can remove a superseding recall's entry.
- **Echo detection:** `SentLog` keeps only one value per address, so a late echo can look like an operator move.
- **Send timeouts:** a GP send that times out returns `Ok`.
- **Health updates:** `set_health` takes `state.write()` on every inbound message.
- **Relative gangs:** the fader position has no upper bound.

**UI performance and behaviour**
- **Per-frame work:** there is an unconditional 50 Hz repaint. `getifaddrs` runs every frame on the Setup tab, the Inspector sorts the whole state while holding the state lock, and the OSC log is cloned every frame (April **M9**, still open).
- **Advanced settings sliders:** dragging one does a synchronous preferences load and save on every frame.
- **Port fields:** invalid port text silently disables the web or monitor server (`unwrap_or(0)`).
- **Macro batch Keep:** keeping steps [A,B,B,A] with {1,3} selected keeps the wrong B (macros_tab.rs:2436-2462).

**Persistence**
- **Save durability:** the temp file name is fixed (`<path>.tmp`), so two concurrent saves can interleave. There's no parent-directory fsync. The rename replaces a symlinked show file with a regular file.
- **Preferences:** saves aren't fsynced, and a parse failure silently resets to defaults, which the next save writes back.
- **Backup rotation and clock skew:** rotation sorts by the timestamp in the file name, so a clock that jumps backwards (a Pi with no RTC) prunes the file just written.
- **Linux EDID:** there's no plausibility range on PPI, unlike Windows.

**Sidecar and MIDI**
- **Touch state:** touch releases dropped while the sidecar is disabled can leave a motor frozen.
- **14-bit MIDI:** LSB-only updates are dropped, and a 14-bit CC ≥ 96 writes to another controller.
- **MIDI trigger engine:** polling adds up to 100 ms of latency, and there's no unplug detection.
- **Linux port names:** ALSA port names change on replug, so saved port matching breaks.

**Probe tool (`examples/d700_probe.rs`)**
- `hidinit` always sends class 0xb0, which the tool's own comment says wedged the device.
- The SysEx 0x70–0x7F sweeps claim "nothing persists", but the control guide records one that needed a full restart.

**Packaging and repo**
- **`.gitignore`:** five patterns never match because of trailing inline comments (`*.dmg`, `*.app/`, `*.iconset/`, `/Output`, `*.AppImage`).
- **Linux installer:** `install-linux.sh` runs `udevadm trigger` with no filter and doesn't check for root.
- **Release workflow:** a signing secret is interpolated into a `run:` script (release.yml:201).
- **Workflow permissions:** `contents: write` is granted workflow-wide, and `ci.yml` has no `permissions:` block.
- **Release artifacts:** there are no signatures or provenance attestations, and the Windows builds aren't Authenticode-signed.
- **Android build:**
  - Release builds are signed with debug keys.
  - `monitor_android/gradlew` isn't executable.
  - The Gradle wrapper has no `distributionSha256Sum`.
- **Repo weight and licensing:**
  - ~48 MB of full CJK OTFs are committed (only needed to regenerate the subsets).
  - There's no SIL OFL text for the bundled Noto fonts.
  - Third-party DiGiCo PDFs are committed.
- **Stale docs:**
  - The main README still sends readers to the Flutter `monitor_app/`, which is not being used (its own README is the Flutter template). Point it at `monitor_android/` and the web monitor, and consider removing or archiving `monitor_app/`.
  - The README says fmt, clippy and audit run on all three OSes.
  - `.iss` defaults to 0.1.1.
  - `todo.md` still lists fixed items 1 and 2 as open.
  - No systemd unit ships for the headless Pi.
- **MSRV:** `rust-version = "1.88"`, but `[lints.rust] float_literal_f32_fallback` is unknown before 1.97. It's only a warning (verified non-fatal under `RUSTFLAGS=-D warnings` on 1.94), but the MSRV isn't exercised in CI.

## Checked and fine (highlights)

- **CIDR:** the maths is correct (`/0`, `/32`, host bits, bad prefixes). All listeners are IPv4-only, so there's no IPv4-mapped IPv6 bypass. The web server's CIDR middleware covers both `/ws` and the static files.
- **Web client:** no path traversal in asset serving. `index.html` uses `textContent` throughout, so there's no XSS.
- **Parsing:** `parse_digico_packet` alignment arithmetic, layout-bank indexing, EQ/dynamics band maps, and pan and bool encodings are correct. Float-to-int casts saturate rather than panic. Every production iPad parse call passes `Some(config)` (April H6 holds).
- **Concurrency:** the AutomationRegistry, SentLog and snapshot engine std mutexes are never held across `.await`. The recall gate and "latest cue wins" behave correctly. Channels are bounded where traffic isn't human-rate. The palette absorb loop drops state before taking the palette lock.
- **Device threads:** no std mutex is held across an await and there's no `block_on` inside async code. Every device loop sleeps or waits with a timeout, and unplugging a device doesn't cause a spin.
- **UI:** no `blocking_read`/`blocking_write`. Fonts are compiled in with `include_bytes!`. Every destructive action is behind a long-press, and quitting while connected asks first. Autosave runs off-thread with an in-flight guard.
- **Platform FFI:** Windows DPI FFI is correct, the EDID parser checks lengths, and the panic hook chains to the previous one.
- **Mobile, packaging and CI:**
  - The "credentials" the Android app stores are only host, port and name.
  - The Kotlin service is `exported=false` with a proper `dataSync` type.
  - The udev rule is scoped to Elgato's vendor ID with mode 0660.
  - The macOS entitlements file is empty, and builds are notarized.
  - CI has no `${{ github.event.* }}` script injection.
  - Every documented CLI flag exists.
